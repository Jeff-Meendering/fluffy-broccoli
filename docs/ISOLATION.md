# Extraction worker boundaries

CLI filesystem scans, durable case captures and desktop scans use `pii-explorer-worker` beside the application by default. Missing helpers cause configuration failure. Builds/installations must include the helper; `cargo build --workspace` builds it for local development. `--in-process` explicitly opts CLI commands into the core library's native in-process extractor. Text-only detection/inference stays in the coordinator and does not invoke the helper.

The coordinator reads and hashes a bounded root file, then sends a versioned JSON header and exact document bytes over stdin. Parsers never receive an evidence filesystem path to open. Nested parsing shares root extraction budgets. The response protocol has a 1 MiB frame limit, 256 MiB total limit, 200,000-record limit, cumulative text/attention budgets, provenance checks and a required completion record. Text frames reassemble into the original extracted parts before detection, preserving coordinates and chunk boundaries. Invalid/incomplete responses discard that root's extraction and produce explicit attention. Filename findings and the source hash remain available.

Workers serve at most 128 roots before replacement. The pool retains at most eight idle workers. On crash, failed IPC, timeout or cancellation, the affected worker is discarded and the next resource receives a new worker. A root deadline includes dispatch and IPC. Unix nonblocking pipes allow cancellation even when the peer never reads input. Diagnostic stderr is discarded because parser messages can include sensitive input. The environment is cleared, with only required Windows system/temp directory variables retained. OCR executable and tessdata paths are passed explicitly.

On Unix, each helper owns a process group. Termination kills that group before reaping the worker, including ordinary OCR descendants. Reader cancellation remains bounded even if a descendant retains an output pipe. Core dumps are disabled and the open-file limit is capped at 256, respecting stricter inherited limits. Linux workers additionally enforce a 1.5 GiB address-space ceiling inherited by OCR children. A worker may fail below a configured input/extraction limit when its memory ceiling is reached; that root is explicitly incomplete. Protocol request ceilings also reject roots above 1 GiB, extracted text above 64 million UTF-16 units, archive expansion above 1 GiB, over 100,000 members or depth above 32. These guardrails do not silently downgrade coverage.

This is parser fault isolation, not exploit containment. Helpers retain the user's filesystem and network permissions. macOS has no enforced address-space ceiling here. Windows currently terminates the direct helper but has no Job Object tree/memory control; inherited Windows pipe handles are not a fully contained boundary. Model inference and source acquisition remain in the coordinator. A restricted OS sandbox, Windows job control and clean-machine platform validation remain acceptance gaps. Do not represent this implementation as a security sandbox.
